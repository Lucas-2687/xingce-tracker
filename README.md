# 行测轨迹 · Xingce Tracker

面向个人备考的行测成绩分析工具，支持仿真模拟、模块练习、趋势分析、跨设备同步与 JSON / CSV 导入导出。

技术栈：Next.js、React、TypeScript、Turso libSQL。支持部署到自己的 Vercel 账户。

采用 [MIT 许可证](./LICENSE)。源码可以共用，每位部署者使用自己的数据库、密码和会话密钥；开源仓库不会提供维护者个人实例的数据或访问权限。

## 本地运行

需要 Node.js 22 或更新版本。

```sh
npm ci
```

将 `.env.example` 复制为 `.env.local`，填写自己的数据库连接信息。运行以下命令生成访问密码哈希：

```sh
npm run password:hash
```

把输出填入 `APP_PASSWORD_HASH`。使用 `.env.example` 中的命令生成随机会话密钥，填入 `APP_SESSION_SECRET`，然后启动：

```sh
npm run dev
```

默认是单人私有应用，不开放注册。不要使用演示密码或复用其他账户密码。

## 部署到 Vercel

1. 在自己的 Turso 账户创建一个 **libSQL** 数据库，取得 URL 和数据库专用读写 token。
2. 在 Vercel 导入自己的源码仓库，选择 Next.js 框架。
3. 在项目 Production 环境中配置下表变量，然后部署。

关联完成后，推送生产分支 `main` 会触发 Vercel 自动构建；其他分支可用于预览。每个部署者使用自己的数据库和登录配置。

| 变量 | 用途 |
| --- | --- |
| `TURSO_DATABASE_URL` | 自己的 libSQL 数据库 URL |
| `TURSO_AUTH_TOKEN` | 数据库专用 token，不使用平台管理 token |
| `APP_PASSWORD_HASH` | 密码工具生成的 scrypt 哈希 |
| `APP_SESSION_SECRET` | 至少 32 字符的随机签名密钥 |
| `APP_OWNER_ID` | 稳定的数据命名空间，默认 `owner` |
| `APP_DISPLAY_NAME` | 页面显示名称 |
| `APP_PREVIEW_ENABLED` | 默认 `false`；仅独立测试配置准备好后，在 Preview 环境设为 `true` |

数据库表在首次访问时自动初始化。后续不要随意更改 `APP_OWNER_ID`。密钥仅放在服务端环境变量中，不加 `NEXT_PUBLIC_` 前缀。

生产凭据只配置在 Production 作用域。Vercel Preview 默认拒绝访问应用和数据 API；需要预览时，配置独立测试数据库、密码和会话密钥，再将 Preview 的 `APP_PREVIEW_ENABLED` 设为 `true`。预览开关不能阻止构建脚本读取已注入的环境变量，必须同时核对 Vercel 对外部贡献和分支构建的授权设置，不向不受信任代码提供生产凭据。运行密钥无需放入 GitHub Actions secrets。

会话最长 7 天。更换密码时，重新运行密码工具，更新 `APP_PASSWORD_HASH` 后重新部署；旧会话会失效。怀疑会话泄露时轮换 `APP_SESSION_SECRET`，使所有旧会话失效。正常退出清除当前浏览器 Cookie，不是服务端逐条撤销签名令牌。数据库 token 应在到期前自行轮换，轮换时保持原数据库和 `APP_OWNER_ID`。

登录限速为 15 分钟内 10 次尝试，跨实例保存在数据库中。Vercel 使用其入口提供的 `x-vercel-forwarded-for`；其他部署不信任客户端转发头，所有访问共用限额。其他反向代理可在入口另加限速，但不能直接信任任意请求提供的 IP 头。

## 数据与备份

仓库不包含真实成绩或运行账户。`src/data/demo.ts` 是合成示例，只有点击“加载演示数据”时才写入应用。

使用“数据管理 → 导出完整 JSON”可以同时备份仿真模拟和模块练习。跨站迁移请导入完整 JSON，等待“已同步”后再次导出核对：

```sh
npm run backup:check -- old-backup.json new-backup.json
```

工具忽略导出时间、记录排列和字段顺序，比较实际内容。备份文件应保存在被忽略的 `backups/` 中，不要提交到仓库。浏览器缓存不会跨域自动迁移。

成绩通过原子版本比较更新同步，冲突返回 409；断网时修改保存在本机。每次保存上限 2 MiB，每类最多 10,000 条记录。

会话到期或数据接口返回 401 时，页面隐藏成绩并停止同步；其他已打开的标签页也会锁定。重新登录后恢复本机未同步修改，仍按版本检查冲突。正常退出前会提醒未同步数据，确认退出后清除当前应用、当前 owner 的缓存；若退出请求失败，页面保持锁定并保留缓存，需重新登录后重试退出。

离线记录和导出的备份均未做应用层加密。页面锁定不能防止拥有本机浏览器配置或磁盘访问权的人读取缓存；公用设备使用后应正常退出，并妥善删除已下载备份。保持原域名、数据库和 owner 更新应用时，无需迁移既有成绩。

## 开发与检查

```sh
npm test
npm run test:privacy
npm run build
npm run typecheck
npm run test:http -- --production
npm run privacy:check -- --history
```

`test:http` 在临时数据库上验证登录、权限、读写、限速及冲突，不使用生产记录；默认验证开发服务，`--production` 验证已构建应用及生产 Cookie 属性。测试会覆盖运行配置，不读取生产数据库。隐私扫描检查工作树、暂存区、未忽略的新文件与完整可达历史，包括提交和标签元数据；只输出脱敏的位置与类别，不输出秘密值。二进制内容和 Git 子模块会阻止扫描通过，需要人工核对后调整发布内容；不把无法检查的内容默认为安全。

启用本地推送前扫描：

```sh
git config core.hooksPath .githooks
```

本地检查用于减少误提交，不能替代人工核对。提交作者、提交者及附注标签作者请使用 GitHub no-reply 邮箱，避免在公开历史中暴露个人邮箱。新增截图、日志或数据文件前，应先检查是否包含个人信息。

完整本地历史检查也包含工具创建的私有 refs。若私有代理快照触发邮箱规则，应先定位其是否属于发布分支，并在只包含拟发布分支/标签的隔离克隆中核验发布内容；不要删除检查规则，或将隔离验证表述为本地所有 refs 都通过。推送时明确指定分支，不使用 `git push --mirror` 将私有快照一起公开。

## 公开发布

先完成 [安全说明中的发布检查](./SECURITY.md)，再将仓库转为公开。工作流 [Checks](./.github/workflows/checks.yml) 在 PR 和推送时执行扫描、测试及构建，不接收生产 secrets；推送改造分支并确认工作流成功后，在 GitHub 分支保护或 ruleset 中将 `checks` 设为合并前必需检查。

PR 工作流检出贡献分支的真实提交，不将 GitHub 自动生成的临时合并身份作为项目提交身份；源码和可达分支历史仍完整扫描。合并保护应要求分支与主分支保持同步。

GitHub secret scanning、push protection 和分支保护取决于仓库及套餐支持情况，需在设置中核验。私有仓库读取分支保护时若提示升级 Pro 或公开仓库，表示当前套餐不支持该功能，不代表代码检查失败。可以先在私有仓库完成 CI 和数据隔离核验，再在正式公开时配置必需检查；若需要保持私有且强制执行保护，应选择支持该功能的套餐。不要为消除 403 而跳过数据检查、提前公开。

工作流文件存在或本地检查通过，不代表这些线上设置已经启用。
